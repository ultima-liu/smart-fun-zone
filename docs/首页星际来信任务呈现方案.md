# 首页任务呈现方案：星环来信

日期：2026-10-02｜状态：第一阶段与来信阅读状态优化已实施。

## 一、重新理解任务入口

上一版“邮差停靠后投出固定光幕”仍是一张换了外形的任务卡。本版让消息本身成为卷星场景里的物件：孩子先**看见一封从远方进入的信**，再主动打开它。首页常驻的是可辨认的收件装置和信件物件，不常驻任务标题卡。

“邮箱”和“漂流瓶”提供两种有价值的体验：邮箱让孩子知道消息送到了哪里，漂流瓶让孩子愿意观察空间。两者不应简单叠成一堆收件入口；主任务必须容易找到，额外邀请才适合探索式发现。

## 二、三个方向的取舍

| 方向 | 首页看到的物件 | 优点 | 限制 |
| --- | --- | --- | --- |
| A. 宇宙邮箱 | 卷星旁的实体收件舱，新信飞入并亮灯 | 主入口明确，低龄孩子容易记住 | 全部任务都进信箱，星空容易只剩装饰 |
| B. 漂流讯息 | 信件或光瓶在星空中缓慢漂行，孩子点击拾取 | 宇宙探索感最强，每封信像一次发现 | 核心课程与到期复习可能被错过；Pad 空间有限 |
| C. 星图雷达 | 星空出现信号波纹，孩子点亮信号读取电文 | 科幻感明确，可与目的地呼应 | “信号”较抽象，对 3–8 岁孩子不如实物直观 |

**实施方向：星环收件站。** 借用 A 的可靠性和 B 的空间趣味：管理端课程表生成的课程邮件、复习和家长约定沿星轨落入收件站；来访挑战、探索和活动以一个漂流物出现在安全区域，孩子主动拾取。没有真实来访内容时不生成装饰性假任务。

## 三、首页画面

### 3.1 收件站是一处真实地点

在卷星外侧星环上放一个小型“星环收件站”：像悬在轨道上的半透明信筒，有收件口、可翻开的舱门和信封灯。它是稳定位置，和学校、乐园一样一眼能再次找到。平时舱门关闭；有当前信件时，收件口露出一角带角色印记的晶体信封。点击**信封或收件站**都能打开当前消息。

收件站不显示“待办 1/7”之类的欠账数字。信箱顶部按“奖励待领取、新来信、继续上课、待处理、新回信”的优先级提示；未读封数与待处理总数分别展示。漂流讯息只在空间中显示自己的拾取提示，不改变信箱状态。卷星上的旧 `🎯1` 假计数移除。

### 3.2 信箱怎样接收来信

信箱显示“新来信”时，自身会周期播放一个轻量接收动作：一枚小信封从信箱右上方滑入收件口并淡出，信箱信号灯随之呼吸。这个动效只发生在信箱附近，不从屏幕外飞入、不拦截学校等地点，也不要求孩子正好看到某一次动画。奖励待领取、已读待处理及继续上课使用静态标记。

信封印记指向真实发送者：阿光、聪聪、兔兔或家人。课程来自学校通讯，不编造“另一颗星球”作为来源。每封信的角色、标题、动作和目的地由稳定任务 ID 对应；当前仅有任务类别时，用已有标题安全回退。

循环接收动效不记录每日或会话次数，但由实际未读状态控制；读过的信返回首页后不再触发新信动效。只在详情区显示过的信才标为已读，按孩子在本机浏览器保存；阅读不会开始课程、完成任务或领取奖励。

### 3.3 漂流物只承载可选的来访

当信箱没有更高优先级的新邮件，同时系统确实有符合条件的来访委托，可在星空边缘出现**最多一个**缓慢漂行的光瓶／晶体碎片。它有角色的小印记，点击后直接打开漂流讯息，不进入收件站，也不会触发信箱的新邮件提示或接收动画。孩子不点击也不会挡住卷星入口。核心课程、到期复习、到期家长任务绝不靠寻找漂流物才能发现。

两条渠道严格分开：收件站只接收课程表邮件、每日复习、家长任务与完成回信；漂流讯息只承载挑战、探索和主题活动。同一时刻只在前景呈现其中一项，避免信箱和空间同时争夺注意力。

这不是把任务随机撒在屏幕上。漂流物的位置来自固定安全区，速度慢且可点击范围稳定；不会随着卷星拖拽跑进建筑或按钮上。没有真实来访时，星空保持空旷。

## 四、打开信后的阅读界面

点击信封，信从收件站升起并展开成“星图信纸”。背景仍隐约可见卷星，信纸自身居中且足够宽。第一眼是发送者印记和一段孩子能听懂的话，不出现“课程任务／探索支线”等后台分类。投影/纸张纹理只承载视觉，不影响文字清晰度。

一封信按以下顺序排版：

1. **谁给我的**：角色头像、名字、来源地点；家长任务标为“家人的来信”。
2. **邀请内容**：一句口语化目标，配一幅与任务内容匹配的小图。课名、活动名和家长原话可展开看全。
3. **目的地**：卷星上对应建筑的小图与“去学校／去复习”等文字。打开时该建筑短暂亮起，形成场景联系。
4. **主要行动**：高度至少 72px 的“开始上课／开始复习／去帮忙／继续完成”，直接进入真实页面。
5. **规则与结果**：挑战阈值、活动日期、家长确认方式在出发前可见；奖励作为次级信息，不用反复弹领奖框。
6. **其他动作**：“自己探索”在底部；关闭信纸返回原卷星位置，不改变任务。

收件站内固定为“当前来信、未完成、已完成”三个分类。每个分类都采用左右双栏：左侧一次列出该分类的全部任务条目，右侧展示当前选中任务的完整内容与主操作；切换条目只更新右侧详情。信箱不提供“稍后处理”，合上信箱也不改变任务状态，任务仍留在原分类中。

管理端按年级配置周一至周五每天的学科；系统到当天为每个学科选择下一节未完成且从未发信的课程，并生成一封独立邮件。同一天可有多封当前来信。当天未领取的邮件留在当前来信，跨日仍未解决的邮件进入未完成，课程完成并领取奖励后进入已完成。只有孩子主动打开收件站时才看到分类，不在首页摆七类任务列表。

### 文案实例

| 情况 | 信封正面 | 打开后的主要内容 |
| --- | --- | --- |
| 课程表数学课 | 阿光的印记＋来信日期 | 完整课名、未开始／未完成／已完成状态、条目奖励｜开始或继续上课 |
| 到期复习 | 聪聪的印记＋“复习来信” | “上次学过的内容，再来试一试吧。”明确课名｜开始复习 |
| 兔兔来访 | 兔兔的印记＋“想请你帮忙” | “帮我配齐三张水果订单！”三步目标｜去帮忙 |
| 家庭约定 | 家人印记＋“家人来信” | 原始约定、提交方式｜我完成了／等待确认 |

短句由内容编辑配置，不能改写题量、课程名称、奖励或家长的原要求。

## 五、信件生命周期

| 状态 | 首页物件 | 打开后 |
| --- | --- | --- |
| 当天课程未开始 | 未读时显示“新来信”，已读时显示“待处理” | 邮件标注日期、课名、奖励和“未开始” |
| 当天课程已开始 | 无更高优先级状态时显示“继续上课” | 状态改为“未完成”，可继续上课 |
| 课程刚完成 | 信箱显示“奖励待领取”，邮件保留原分类 | 状态改为“已完成 · 待领奖”，课程奖励尚未入账 |
| 奖励已领取 | 邮件从当前来信移走 | 进入已完成，稳定奖励键阻止重复领取 |
| 跨日仍未解决 | 按实际阅读、开始和奖励状态提示，不把已读邮件伪装成新信 | 进入未完成；完成待领奖的旧邮件也保留领奖入口 |
| 家长待确认 | 家人信封换成“已回传”印章 | 等待确认，不可重复提交 |
| 主动安静／无建议 | 收件站关门，仍可打开看旧信与成果 | 自由探索；不显示假未读 |

课程邮件只在课程表指定的上课日生成，每个学科最多一封。系统按教材顺序跳过已经完成或已经发过信的课程；完成一课不会立刻投递下一课，要等后续课程表中的对应学科上课日。章节和其他任务使用各自规则，不改变课程邮件分类。来访主动次数、优先级、暂缓和 30 分钟安静规则仍由现有任务系统决定。

## 六、动效、声音与适配边界

- 实际未读来信触发简短的信封滑入动作和“新来信”提示；奖励待领取、已读待处理和继续上课使用独立静态标记。阅读信纸时暂停背景与卷星动效，合上后恢复。漂流物缓慢移动但不闪烁催促，完成课程不自动触发下一封。
- 声音开启时投递只播放短提示；用户已有交互后每封信最多自动朗读一次邀请。信纸上有“再听一遍”，静音下所有信息仍可阅读。
- `prefers-reduced-motion` 时信封直接出现在收件站，漂流物静止，打开信纸仅淡入。动画失败不影响打开与出发。
- Web 接收站利用卷星外侧安全区；Pad 横竖屏将收件站排到卷星下方。收件站在 Web 与 Pad 均保持左侧任务列表、右侧任务详情的双栏结构，窄手机尺寸才改为上下排列。任何尺寸都不能遮住学校、乐园、远征战利品、学习助手和关闭入口。漂流物触控区域至少 72px；其他可点击元素至少 44px。深浅主题保持文字对比。
- 课程完成只更新邮件状态；奖励必须由当前来信或未完成分类中的领取按钮发放。周期动画不保存播放次数，也不能因为孩子没点信封就改变课程表。

## 七、实施与验收建议

1. 已用收件站、信封和星图信纸替换固定航行通讯与原三标签主面板，接通课程、复习、暂停、完成和家长任务状态。
2. 已加入信箱自身的周期接收动效、逐封已读状态、奖励待领取和成果回信提示；动效不记录每日或会话次数，由实际未读状态控制。
3. 已为实际送达的来访任务加入一个漂流物；核心任务始终进入收件站，缺少来访内容时不制作假信号。

验收时让孩子在首页指出“新信在哪里”、打开后说出“谁邀请我做什么”、点一次进入真实内容；验证周期动效只在信箱局部运行、阅读后该封信不再提示为未读、任务保留且完成后不自动催下一项，并覆盖 Web、Pad 横竖屏、触控、键盘、静音与减少动态效果。
