# 架构设计

状态：当前工程边界基线（2026-09-28）

## 核心原则

- 产品主链固定为「今日课程 → 到期复习 → 获得奖励 → 乐园放松」。课程掌握度与休闲街机成绩严格分离。
- 前端本地优先：离线时学习不被阻断；登录后才启用云端备份与跨设备恢复。
- 云端按账号与儿童双重隔离。任何 query/body 中的 `childId` 都只是请求目标，必须经过服务端所有权校验。
- 课程内容、运行状态和持久化职责分离。页面负责交互呈现，领域模块负责结算与迁移。

## 模块边界

- `src/content/`：课程、物品、图鉴等静态定义，不直接写浏览器存储。
- `src/pages/`：路由级页面和课程编排，不直接决定账号权限。
- `src/store.ts`：当前本地领域状态与迁移；后续新增能力优先放入独立领域模块，避免继续扩大单文件。
- `src/cloud.ts` / `src/autosync.ts`：同步适配层。一次拉取形成课程、积分与物品快照，账号缓存键互相隔离。
- `server/src/access.ts`：儿童数据统一访问策略。
- `server/src/app.ts`：HTTP 编排；业务规则应逐步下沉到领域服务。

## 数据事实来源

- 未登录：浏览器持久化数据是事实来源。
- 已登录：服务端保存跨设备事实，本地保存可离线继续的副本；进度按更新时间合并，幂等奖励按 source id 合并。
- 账号映射、错题上传游标等同步元数据必须包含账号作用域，不得跨账号复用。
- Service Worker 永不缓存 `/api/**`。

## 后续拆分约束

当页面或领域文件超过约 600 行，新增功能前应优先拆出内容定义、纯规则、持久化适配或展示组件。拆分必须保持用户行为与现有存档兼容，不以重写为目的。
