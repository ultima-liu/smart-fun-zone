# 管理员后台（`/admin`）· 账号与启动依赖

> 相关代码：`server/src/index.ts`（引导管理员）、`server/src/app.ts`（登录接口）、`src/pages/AdminPage.tsx`（登录页）

## 1. 默认账号

| 项 | 值 |
|---|---|
| 登录名 | `admin`（可用环境变量 `ADMIN_LOGIN` 覆盖） |
| 默认密码 | `admin123`（可用环境变量 `ADMIN_PASSWORD` 覆盖） |
| 角色 | `admin` |
| 昵称 | 管理员 |

- 引导逻辑 `bootstrapAdmin()` 在服务启动时执行：**仅当 `users` 表中不存在该 `login_name` 时创建**；已存在则不覆盖，因此**改过密码后不会退回默认值**，之后修改 `ADMIN_PASSWORD` 对已存在的账号无效。
- 忘记密码时：用另一个管理员账号调 `PATCH /api/admin/parents/:id`（body 含 `password`）重置；或直接更新数据库中该账号的 `login_hash`（scrypt，`salt:hash` 格式）。
- ⚠️ 对外环境务必用环境变量设置强密码，不要沿用默认值。

## 2. 前置条件：后端必须启动

管理员登录走 `POST /api/auth/parent-login`，由后端（Fastify，默认 `127.0.0.1:8787`）校验，Vite 把 `/api/*` 代理到该端口。

```bash
cd server && npm start          # 或 npm run dev（tsx watch）
```

- 后端未启动时：前端 `src/api.ts` 的 `request()` 在 fetch 失败时**静默返回 `null`**，`AdminPage.doLogin` 会把 `null` 一律当作失败，于是**无论账号密码是否正确都提示「账号或密码不正确」**，容易误判为密码错误。
- 排查建议：先确认 8787 有监听（`curl http://127.0.0.1:8787/api/health` 应返回 `{"ok":true,...}`），再怀疑账号密码。
- 待改进（可选）：把“网络/服务端不可用”与“账号密码错误”的提示区分开。

## 3. 登录请求示例

```bash
curl -X POST http://127.0.0.1:8787/api/auth/parent-login \
  -H 'content-type: application/json' \
  -d '{"loginName":"admin","password":"admin123"}'
# → { ok: true, token, userId, role: "admin", nickname }
```
